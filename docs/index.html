LC Hack

Repository Download

A hacking minigame built around a fake Linux terminal and desktops. Players read files, scan networks, hop between machines with ssh and rdp and get past firewalls until they have root access on the target machine. Passwords never leave the server.

Installation

Install all resource dependencies

  • ox_lib
  • ox_target (optional, terminals use ox_lib points with [E] without it)
  • OneSync, the server checks the player's position when a terminal is used.

Download a release or clone the source code

  • Download the latest release.
  • Or clone the repository: git clone https://github.com/LAURIDS0/lc_hack.git

Start the resource

Start lc_hack after its dependencies in your server.cfg.

ensure ox_lib
ensure ox_target
ensure lc_hack

Try it

Two test commands are included in server/commands.lua. Both require the group.admin ace.

  • /hack opens the example network on yourself.
  • /hackterminal creates a test terminal at your position.

The example is solved by reading /var/mail/alex, running ssh backup@10.0.0.12, reading /opt/backup.sh, running ssh dbadmin@db-server, reading ~/.mysql_history and finally su.

How it works

  • Configs live on the server. The client receives a copy without password and rootPassword.
  • Every password attempt (ssh, rdp, su, sudo) is checked by the server, which also counts attempts.
  • The server decides when the player wins (root on the target) and calls your callbacks.
  • File contents are sent to the client so the player can read them. A cheater could read them directly, but still has to send the correct root password to the server to win.

HackConfig

A hack is described by a single table. The top-level fields describe the player's own machine plus a few game settings, and every machine in network uses the same machine fields.

Game

Only used at the top level.

  • target?: string
    • IP of the machine the player needs root access on. Defaults to the player's own machine.
  • attempts?: number
    • Wrong passwords allowed in total across ssh, rdp, su and sudo. Defaults to 3.
  • network?: HackMachine[]
    • The other machines. Machines without an ip are ignored.

Machine

Used at the top level and in every entry of network.

  • ip?: string or string[]
    • The machine's IPs. More than one IP puts the machine on several networks. Defaults to '10.0.0.20' for the player's own machine.
  • host?: string
    • Hostname shown in the prompt, hostname and nmap. Defaults to 'pc'.
  • user?: string
    • The user the player logs in as. The home directory is /home/<user>. Defaults to 'user'.
  • password?: string
    • The user's password for ssh and rdp. Without it, no password is asked for.
  • rootPassword?: string
    • Root password for su and sudo. Without it, the player becomes root without a password.
  • desktop?: 'ubuntu' or 'windows' or 'kali' or 'macos' or 'random'
    • Graphical desktop, see Desktops. CLI only without it.
  • ports?: number[]
    • Services the machine runs, e.g. 22 (ssh), 80 (http), 3306 (mysql), 3389 / 5900 (remote desktop). Defaults to { 22 }, plus the remote desktop port when the machine has a desktop.
  • firewall?: table
    • See Firewall. No firewall without it.
  • processes?: string[]
    • Extra processes shown in ps aux, running as root.
  • files?: table<string, string>
    • Your own files as [path] = content, see Files.
  • locked?: string[]
    • Extra paths only root can read, e.g. { '~/secret.txt' }.

Firewall

  • allow?: string[]
    • IPs that may do anything.
  • open?: number[]
    • Ports anyone may use.
  • ping?: boolean
    • Answer ping from anyone. Defaults to false.

firewall = {} blocks everything from the outside. See Networking for how traffic is checked.

Files

Every machine gets around 90 default Linux files, built with its own user, host and IPs. Your files are added on top.

  • ~ is the machine's home directory. Absolute paths work too.
  • Directories are created automatically.
  • Files starting with . are hidden and only shown with ls -a.
  • Using the same path as a default file replaces it, e.g. /etc/hosts or /opt/backup.sh.
  • Contents are plain text. Use \n for new lines.
  • /var/www/html/index.html is what curl shows when the machine has port 80.

By default only root can read /root, /etc/shadow, /etc/sudoers, /var/backups/shadow.bak and ~/.ssh/id_rsa.

The default files contain fake passwords to mislead players. Do not use these as real passwords:

Fake passwordFound in
toor~/.bash_history
Pa$$w0rd!/var/www/html/config.php
changeme/opt/backup.sh
summer2019, Football123, 12345678~/Documents/old_passwords.txt

Example

local config = {
    -- The player's own machine
    ip = '10.0.0.20',
    host = 'workstation',
    user = 'alex',
    desktop = 'ubuntu',
    files = {
        ['/var/mail/alex'] = 'User: backup\nPassword: Secure2026',
    },

    -- Game
    target = '192.168.1.5',
    attempts = 5,

    -- Other machines
    network = {
        {
            ip = { '10.0.0.12', '192.168.1.10' },
            host = 'backup-srv',
            user = 'backup',
            password = 'Secure2026',
        },
        {
            ip = '192.168.1.5',
            host = 'db-server',
            user = 'dbadmin',
            password = 'Tr0ll3y!',
            rootPassword = 'Fjord#88',
            ports = { 22, 3306 },
            firewall = { allow = { '192.168.1.10' } },
        },
    },
}

Client

Hacks are always started by the server, see Server. The client can only check and close the terminal.

isOpen

Checks if the hack terminal is open.

exports.lc_hack:isOpen()

Return:

  • boolean - Returns true if the terminal is open, otherwise false.

Example

if exports.lc_hack:isOpen() then return end

close

Closes the terminal. This counts as giving up, like pressing Escape.

exports.lc_hack:close()

Server

All server exports take a HackConfig. They throw an error on invalid types, e.g. expected data.coords to have type 'vector3' (received nil).

createTerminal

Creates a new hack terminal in the world. With ox_target it becomes a sphere zone, otherwise an ox_lib point with [E].

exports.lc_hack:createTerminal(data)
  • data: table
    • coords: vector3
    • config: HackConfig
    • name?: string
      • An optional name to refer to the terminal instead of using the id. Using the same name again replaces the old terminal.
    • label?: string
      • Text shown by ox_target or the [E] prompt. Defaults to 'Hack terminal'.
    • radius?: number
      • How close the player has to be. Defaults to 1.5.
    • onSuccess?: function(source: number, id: number | string)
      • Called when the player gets root on the target. id is the name if one was set.
    • onFail?: function(source: number, id: number | string)
      • Called on too many wrong passwords, Escape, exit or when the player drops.

Return:

  • id: number

Terminals are removed automatically when the resource that created them stops. Several players can use the same terminal at the same time, each in their own hack.

Example

exports.lc_hack:createTerminal({
    name = 'bank_server',
    coords = vec3(253.1, 228.4, 101.7),
    label = 'Use server',
    config = {
        user = 'teller',
        desktop = 'windows',
        target = '10.1.0.10',
        network = {
            { ip = '10.1.0.10', host = 'bank-core', user = 'ops', password = 'Vault#2026', rootPassword = 'Valv-7781' },
        },
    },
    onSuccess = function(source, id)
        -- reward the player, open a door, etc.
    end,
    onFail = function(source, id)
        -- trigger an alarm, etc.
    end,
})

removeTerminal

Removes a terminal.

exports.lc_hack:removeTerminal(id)
  • id: number or string
    • The id returned by createTerminal, or the terminal's name.

Return:

  • boolean - Returns true if a terminal was removed.

terminalExists

Checks if a terminal exists.

exports.lc_hack:terminalExists(id)
  • id: number or string

Return:

  • boolean - Returns true if the terminal exists, otherwise false.

startHack

Opens a hack directly on a player, without a terminal. Useful for items and jobs.

exports.lc_hack:startHack(source, config, cb)
  • source: number
  • config: HackConfig
  • cb?: function(success: boolean)
    • Called when the hack ends.

Return:

  • started: boolean - false if the player is already hacking.

Example

exports.lc_hack:startHack(source, config, function(success)
    if success then
        -- reward the player
    end
end)

stopHack

Stops the player's hack and closes the terminal. Counts as a failure, so cb(false) or onFail is called.

exports.lc_hack:stopHack(source)
  • source: number

isHacking

Checks if a player is currently hacking.

exports.lc_hack:isHacking(source)
  • source: number

Return:

  • boolean - Returns true if the player is hacking, otherwise false.

Networking

Machines are connected through simple /24 networks. Building a network is mostly about choosing IPs and firewalls so the player has to find the right path.

Rules

  • Two machines can only reach each other when they have an IP on the same /24 network (the first three numbers match, e.g. 10.0.0.x).
  • A machine with several IPs, e.g. { '10.0.0.12', '192.168.1.10' }, connects two networks. To reach 192.168.1.x, the player has to ssh into it first.
  • There is no routing and no DNS. Hostnames like db-server are looked up in /etc/hosts on the current machine, so replace /etc/hosts in a machine's files to make a name work.
  • arp remembers every machine the player tried to contact, even when a firewall blocked it.

Firewall

firewall = {
    allow = { '192.168.1.10' }, -- these IPs may do anything
    open = { 80 },              -- these ports are open to everyone
    ping = false,               -- answer ping from everyone
}
  • The IP that is checked is the player's IP on the same network as the target.
  • nmap shows blocked ports as filtered. A host that answers neither ping nor port 80/443 looks down, and nmap -Pn scans it anyway.
  • As root, the player can change a firewall with ufw disable, ufw allow 22 or ufw allow from <ip>. Changes last until the terminal closes.

Desktops

Besides the CLI, a machine can have a graphical desktop. All desktops have the same apps; only the look and the app names change.

desktopLookTerminalFilesEditorRemote desktop
'ubuntu'Top bar, dock on the leftTerminalFilesText EditorVNC, port 5900
'windows'Taskbar at the bottomWindows TerminalFile ExplorerNotepadRDP, port 3389
'kali'Dark top panel with appsQTerminalThunarMousepadVNC, port 5900
'macos'Menu bar, dock at the bottomTerminalFinderTextEditVNC, port 5900
'random'One of the four, picked every time the terminal opens

Access

  • If the player's own machine has a desktop, the hack starts on it.
  • startx opens the desktop of the current machine.
  • rdp [user@]host opens a remote desktop on another machine. It needs port 3389 or 5900, goes through the firewall and asks for the user's password, checked by the server.
  • The power button closes the desktop. If it was opened with rdp, it also logs off that machine.

A machine with a desktop and no ports gets { 22, 3389 } (Windows) or { 22, 5900 } (others). When you set ports yourself, add the remote desktop port if rdp should work. For 'random', add both.

Apps

  • Terminal - the real CLI in a window. It shares the login stack, so ssh, su and everything else works. Closing the window keeps its history.
  • Files - browse the desktop machine's files. Double click a folder to open it and a file to open it in the editor. Locked files show a lock and an error dialog. The Hidden checkbox shows files starting with ..
  • Text Editor - shows a file read-only.

Windows can be moved by their title bar, brought to the front by clicking and closed. The file manager always shows the desktop's machine, even after ssh-ing elsewhere in the terminal. The Windows desktop shows paths as C:\home\alex, but uses the same Linux filesystem.

Extending

How lc_hack is put together, and where to add your own commands, apps and desktops.

Structure

FileResponsibility
server/main.luaEntry point, requires the modules below.
server/api.luaExports and LuaLS types.
server/session.luaRunning hacks: passwords, attempts, win and loss.
server/terminal.luaTerminals in the world and the distance check.
server/commands.luaTest commands and the example config.
client/main.luaEntry point, requires the modules below.
client/api.luaClient exports.
client/terminal.luaOpens and closes the NUI and forwards password attempts.

web/js/desktop.jsDesktops, windows, Files and Text Editor.
web/css/style.css, web/css/desktop.cssThe CLI and the four desktop themes.

New client files must be listed in files in fxmanifest.lua, otherwise require can't find them.

Flow

  1. The player uses a terminal and the client triggers lc_hack:use. The server checks the distance and starts a session.
  2. The server sends the config without passwords with lc_hack:open.
  3. When the player submits a password, terminal.js sends it through the NUI to client/terminal.lua and on to lc_hack:verify.
  4. The server checks it, counts attempts and decides the outcome. The answer goes back to terminal.js.
  5. When the hack ends, the server calls onSuccess, onFail or the cb from startHack.

Machines have an index (1 is the player's own, 2+ is network in order), so the server knows which machine a password is for. kind is 'login' (ssh, rdp) or 'root' (su, sudo).

Adding a command

Add a function to commands in web/js/terminal.js. It receives the words after the command as a list and works with Tab automatically. Add it to help as well.

// "whois 10.0.0.5" -> args = ['10.0.0.5']
whois(args) {
    const m = findMachine(args[0]);
    print(m ? `${args[0]} is ${m.host}` : 'whois: unknown host');
},

Adding a desktop app

Create a function in web/js/desktop.js that builds an element and calls createWindow, then add it to the dock with dockButton in openDesktop. Icons are Font Awesome classes.

function openCalculator() {
    const body = el('div', 'editor', '2 + 2 = 4');
    createWindow('Calculator', body, { width: 260, height: 160 });
}

dock.append(dockButton('fa-solid fa-calculator', 'Calculator', openCalculator));

Adding a desktop

  1. Add its name to DESKTOPS and DESKTOP_PROCESS in terminal.js.
  2. Add its app names and menu icon to THEMES in desktop.js.
  3. Add a .theme-<name> block to desktop.css that places .panel and .dock and colours .window and .titlebar.

Default files and ports

  • Add default files in defaultFiles(). A path ending with / is an empty folder, and user, host and ips can be used in the text.
  • Lock a default file by adding its path to DEFAULT_LOCKED.
  • Name a port for nmap in SERVICES.

Limitations

  • No pipes (|), redirection (>), rm, mkdir or editing files, also not in the text editor.
  • grep works on a single file and is case-sensitive.
  • One desktop at a time. rdp to another machine closes the current one.
  • One hack per player at a time, and no cooldown on terminals.
